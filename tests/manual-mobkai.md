# Manual Test Specification: Mobkai (minimal mobile note mode), Lots 1 to 4

## Overview
Mobkai is Famouskai on a phone, stripped down to the menu bar, the file name, the editor, the Markdown preview and the bottom status bar. Lot 1 covers the detection and what is hidden or turned off. Lot 2 covers touch ergonomics, clean editor framing, Ace mobile menu removal, 44px hit targets, 360px fit, and Preview restriction. Lot 3 covers the bottom status bar: "Copy all" button, toasts in the bar, app version when idle, and virtual keyboard behavior. Lot 4 covers draft recovery for the [New] note on app switch or tab termination. Spec: `docs-lab/MOBKAI-SPEC.md` (sections 3, 4, 6, 7, 8, 13, 14).

## Scope
- Detection: automatic on a phone, `?mobkai=1` / `?mobkai=0` / `?mobkai=auto` override.
- Hidden: sidebar, drawer, tool buttons, export, print, Full View, preview theme, new window, Move, Reload, version, browser banner.
- Turned off: autosave, auto-cleanup on Save and on Open, Diffskai (a simple confirm on conflict).
- Lot 2 Touch & Editor: no Ace mobile menu (native OS selection handles), editor frame 100dvh (no page scroll), Ace options (16px, wrap, no gutter, no active line highlight, 8px padding), 44px touch targets on menu bar, 360px viewport fit without wrapping, Preview button shown only for `.md` files.
- Lot 3 Status Bar: bottom status bar with "Copy all" on the left, toast messages on the right, version string on the right when idle, stays above the virtual keyboard.
- Lot 4 Draft Recovery: one draft in localStorage for `[New]` note only, saved on visibility change (hidden) / pagehide, offered back on reboot via confirm dialog, restored with unsaved indicator, removed on Cancel, Save or New.
- Desktop unchanged.

Devices: Samsung Galaxy S23 and Galaxy Note 11, in Chrome and in Firefox for Android. Desktop: Chrome on the usual Chromebook.
